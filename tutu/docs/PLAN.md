# Tutu — план продукту

> Скануєш тіло iPhone → отримуєш 3D-модель → малюєш на ній, де буде тату →
> регіон автоматично «розгортається» в плаский шаблон → у розгортці редагуєш
> ескіз або генеруєш його ШІ → бачиш результат на тілі в 3D і друкуєш
> трансферний трафарет у реальному масштабі 1:1.

## 1. Для кого і навіщо

| Користувач | Біль | Що дає Tutu |
|---|---|---|
| Клієнт, що хоче тату | Важко уявити, як ескіз ляже на руку/спину, як зміниться при вигині | Примірка на власному 3D-тілі, ШІ-генерація ідей |
| Тату-майстер | Ескіз на папері ≠ форма на тілі; трафарет переробляють кілька разів | Розгортка регіону = точний трафарет під конкретне тіло, друк 1:1 |
| Студія | Довгі консультації, втрачені ліди | Посилання на проєкт, спільне редагування, портфоліо |

**Ключова цінність (що відрізняє від «наклейки на манекені»):** розгортка
регіону з мінімальними спотвореннями (конформне відображення LSCM). Те, що ти
намалював у розгортці, — це рівно та форма, яку треба перенести на шкіру.

## 2. Архітектура

```
┌────────────── iOS app (SwiftUI) ──────────────┐
│ ARKit LiDAR scene reconstruction → меш (OBJ)  │
│ Підказки зі сканування, обрізка, чистка       │
│ WKWebView ── вбудований редактор (той самий,  │
│              що у вебі) через JS-міст         │
└───────────────┬───────────────────────────────┘
                │ HTTPS (REST)
┌───────────────▼───────────────────────────────┐
│ Backend (Python, FastAPI)                     │
│  /api/scans     — завантаження мешів          │
│  /api/projects  — проєкти (меш+регіон+шари)   │
│  /api/generate  — генерація ескізів           │
│  Провайдери: OpenAI Images / Replicate / mock │
│  (далі) черга задач, обробка мешів, SMPL-X    │
└───────────────▲───────────────────────────────┘
                │
┌───────────────┴───────────────────────────────┐
│ Web-редактор (TypeScript + Three.js + Vite)   │
│  3D-в'юпорт: кисть виділення регіону на тілі  │
│  LSCM-розгортка регіону → 2D-полотно          │
│  Шари: зображення, ШІ-ескізи, малювання тушшю │
│  Живий перегляд на тілі, експорт трафарету 1:1│
└───────────────────────────────────────────────┘
```

Чому редактор — веб, а не нативний: один код для iPhone (WKWebView), iPad,
десктопу майстра і посилань «подивись мій ескіз». Нативною лишається частина,
яка вимагає заліза: сканування LiDAR/камерою.

## 3. Етапи

### Етап 0 — Фундамент ✅ (зроблено в цьому коміті)
- Монорепо `tutu/`: `web/`, `server/`, `ios/`, `docs/`.
- CI (GitHub Actions): збірка вебу, тести бекенду і ядра розгортки.

### Етап 1 — Ядро редактора (MVP) ✅ (зроблено)
- **10 реалістичних базових тіл: 5 чоловічих і 5 жіночих статур** (худорлявий, середній,
  атлетичний, кремезний, повний / струнка, середня, спортивна, пишна, повна).
  Анатомія — з відкритої моделі MakeHuman (CC0, побудована на вимірах реальних людей):
  правильні пропорції, лице, кисті, стопи. Повзунки: зріст (см), вага, м'язи, груди;
  оцінка маси тіла за об'ємом. Генерація — **на сервері** (0.03 с), клієнт отримує лише меш.
  У всіх тіл однакова сітка, тож при зміні статури ділянка й ескіз зберігаються.
- Швидкий фокус камери: передпліччя, плече, груди, живіт, спина, шия, стегно, гомілка.
- Завантаження власних мешів OBJ / GLB / GLTF / PLY / STL + крупні плани частин тіла
  у реальному масштабі (метри) — додатково.
- Кисть виділення регіону прямо на 3D-тілі (додати / стерти, розмір кисті),
  зростання регіону тільки по зв'язній поверхні.
- **Розгортка LSCM** (Least Squares Conformal Maps) — власна реалізація,
  з нормалізацією до реального масштабу (см) і контролем дзеркальності.
- 2D-полотно розгортки: сітка регіону, шари-зображення (переміщення, масштаб,
  обертання), малювання тушшю, гумка, «трафаретний» фільтр (чорна лінія на прозорому).
- Живе накладання на 3D (окремий патч-меш поверх тіла).
- Експорт трафарету PNG у 300 DPI у реальному розмірі + знімок 3D-виду.

### Етап 2 — ШІ-генерація ✅ (базово зроблено)
- `/api/generate`: стильові пресети (fine line, blackwork, traditional,
  geometric, watercolor, minimal), промпт-інжиніринг під «tattoo flash на
  білому тлі».
- Провайдери: OpenAI Images (за наявності `OPENAI_API_KEY`), mock-генератор
  (працює офлайн, для розробки й тестів).
- У редакторі: панель генерації → результат одразу стає шаром у розгортці.
- **Далі:** генерація з урахуванням форми регіону (маска розгортки →
  inpainting/outpainting, щоб ескіз «заповнював» форму), варіації, історія.

### Етап 3 — iOS 🟡 (каркас зроблено, потрібна збірка в Xcode)
- Головний сценарій — базові тіла, як у вебі. **LiDAR-сканування — додаткова функція**
  (видно лише на пристроях з LiDAR; застосунок ставиться на будь-який iPhone).
- SwiftUI-застосунок, ARKit `sceneReconstruction = .mesh` (iPhone Pro з LiDAR).
- Накопичення `ARMeshAnchor` → злиття → експорт OBJ через ModelIO.
- Екран сканування з підказками («обійдіть повільно по колу», якість, кількість
  трикутників), завантаження на сервер, відкриття редактора у WKWebView.
- **Далі:**
  - обрізка зайвого (підлога, фон) — сегментація людини `ARFrame.segmentationBuffer`
    / Vision `VNGeneratePersonSegmentationRequest` під час сканування;
  - режим «скануй сам себе»: фронтальна TrueDepth-камера для частин тіла;
  - для iPhone без LiDAR: відео → фотограмметрія на сервері.

### Етап 4 — Якість моделі тіла
- ✅ Реалістична параметрична модель (MakeHuman CC0) замість процедурної.
- Далі: більше повзунків (обхвати талії/стегон/грудей у см → підгонка під заміри клієнта),
  опційна білизна на моделі, тон шкіри.
- LiDAR-меш грубий (~1–2 см) і «шумний». Рішення:
  1. Пост-обробка на сервері: очищення, заповнення дір, ремеш
     (Open3D / PyMeshLab), згладжування Taubin.
  2. **Підгонка параметричної моделі тіла (SMPL-X)** за сканом + фото →
     гладка, анатомічна, з правильною топологією і скелетом.
  3. Текстура шкіри з кадрів сканування (проєкція фото на меш) — реалістична
     примірка з урахуванням тону шкіри.

### Етап 5 — Професійні функції розгортки
- Розріз-шов для замкнених регіонів (повне кільце на руці, «рукав»).
- Карта спотворень (heatmap площі/кутів) прямо на полотні.
- Сітка-лінійка в см, прив'язки, симетрія.
- Векторні шари (SVG), імпорт ескізів майстра, PSD-експорт.
- Анімація «як тату деформується при згинанні» (скелет SMPL-X).

### Етап 6 — Продукт і бізнес
- Акаунти (Sign in with Apple), хмарне сховище проєктів, шерінг за посиланням.
- Маркетплейс майстрів: клієнт надсилає проєкт → майстер дає оцінку/запис.
- Монетизація: freemium (N генерацій/міс), Pro для майстрів (друк трафаретів,
  брендування, CRM клієнтів).
- Приватність: скани тіла — чутливі дані. Шифрування, видалення на вимогу,
  обробка на пристрої де можливо, GDPR.

### Етап 7 — Реліз
- TestFlight → App Store, веб на власному домені.
- Аналітика воронки (скан → регіон → ескіз → експорт), краш-репорти.
- Модерація генерацій (заборонений контент) на боці провайдера + власні фільтри.

## 4. Технічні рішення і ризики

| Ризик | Рішення |
|---|---|
| Людина не може відсканувати себе сама | Скан робить інша людина; для частин тіла — режим TrueDepth; далі — SMPL-X з кількох фото |
| LiDAR лише на Pro-моделях | Фолбек: фотограмметрія з відео на сервері; або параметрична модель з фото |
| Регіон — не диск (кільце навколо руки) | Етап 5: автоматичний шов; зараз — попередження |
| Вартість генерацій | Кеш, ліміти, дешеві моделі для чернеток, дорогі — для фіналу |
| Чутливість даних | Мінімізація: зберігаємо тільки меш без текстури за замовчуванням |
